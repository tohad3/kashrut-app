# ניהול כשרות – אפליקציה למערכת "שירת הים"

אפליקציית ווב (PWA) שעובדת באייפון, באנדרואיד ובמחשב. מתחברים עם שם המשתמש והסיסמה של
https://shirathayam.m-datit.org.il ומקבלים:

- **דשבורד**: מדדים, סטטוסים, סוגי עסקים, אזורים, רמות כשרות, דיווחי משגיחים ב־14 הימים האחרונים ואחוז דיווחים בטווח לכל משגיח.
- **מפת עסקים**: כל בתי העסק על המפה בצבע לפי סטטוס, עם סינון לפי סוג, רמת כשרות וחיפוש.
- **מפת נוכחות**: דיווחי משגיחים לפי טווח תאריכים ומשגיח. ירוק = כניסה ויציאה בטווח, כתום = חלקי, אדום = מחוץ לטווח.
- **בתי עסק**: חיפוש וכרטיס לכל עסק עם תעודות כשרות, **עדכון פרטים** (שם, חברה, שם על השיק, דוא"ל, תיאור, הערות) ו**עדכון מיקום** על המפה או לפי המיקום הנוכחי של הטלפון.

כל עדכון נשמר ישירות באתר "שירת הים", ולפני השמירה מוצגת בקשת אישור.

## איך זה עובד

```
טלפון / מחשב  ──►  server.js (השרת שלך)  ──►  shirathayam.m-datit.org.il
   (PWA)            מתחבר בשמך ומעביר
                    רק קריאות מוגדרות
```

- הסיסמה עוברת לאתר בזמן הכניסה בלבד ו**לא נשמרת**. השרת שומר בזיכרון את עוגיית ההתחברות, והיא נמחקת אחרי שעה בלי פעילות או ביציאה.
- מיקומי בתי העסק נטענים מהאתר פעם אחת (כפתור "טען מיקומים") ונשמרים בקובץ `data/coords-<מועצה>.json`, כי האתר לא מחזיר מיקומים ברשימה המרוכזת.

## הרצה במחשב

1. מתקינים Node.js בגרסה 18.14 ומעלה (https://nodejs.org), או מריצים:
   ```bash
   winget install OpenJS.NodeJS.LTS
   ```
2. בתיקיית האפליקציה מריצים:
   ```bash
   node server.js
   ```
3. פותחים את http://localhost:3000

## שימוש מהטלפון

בטלפון, מיקום GPS והתקנה כאפליקציה ("הוסף למסך הבית") עובדים רק בכתובת **HTTPS**. יש שתי אפשרויות:

- **שרת של המועצה או שרת ענן** (למשל Render, Railway או Azure App Service): מעלים את התיקייה ומגדירים פקודת הפעלה `node server.js`. השירותים האלה נותנים HTTPS אוטומטית. חשוב: אתרים ממשלתיים חוסמים לפעמים כתובות IP מחוץ לישראל, לכן עדיף שרת באזור ישראל (Azure Israel Central או שרת מקומי).
- **מנהרה מהמחשב** (לבדיקות): `cloudflared tunnel --url http://localhost:3000` נותן כתובת HTTPS זמנית.

## עדכון אוטומטי מ-GitHub

במחשב HAIFA-KASH רצה משימה מתוזמנת (`kashrut-auto-publish`) כל 5 דקות שמריצה את `auto-publish.ps1`. היא מושכת קוד חדש מ-GitHub, ואם יש שינוי מריצה `publish-code.js`, כך ששינוי שנדחף ל-GitHub מגיע לכל המשתמשים בלי לגעת במחשב. ברשת המועצה git עובר דרך ה-Proxy `192.168.155.13:8080` (מוגדר ב-`git config --global http.https://github.com.proxy`). יומן: `Documents\kashrut-auto-publish.log` (נכתב רק כשיש עדכון או שגיאה).

## התקנה אצל עמית חדש

בלי קובץ exe (קובץ exe לא חתום נחסם ב-SmartScreen):

1. משתפים איתו את התיקייה המשותפת, והוא לוחץ "הוסף קיצור דרך לקבצים שלי" ומחכה לסנכרון.
2. בתיקייה, לחיצה ימנית על `התקנת ניהול כשרות.ps1` ואז "הפעל באמצעות PowerShell".

הסקריפט (`installer/install.ps1`) מעתיק את `_app` ואת `_app\node\node.exe` ל-`C:\Users\<שם>\kashrut-app`, יוצר קיצור דרך בשולחן העבודה ובתפריט התחל ופותח את האפליקציה. `publish-code.js` מפרסם את הסקריפט לתיקייה המשותפת ומעתיק לשם את Node. גרסת ה-exe (NSIS, `installer/build.sh`) נשארה במאגר אבל לא מתפרסמת.

קיצור הדרך נבנה מחדש בכל הפעלה על ידי `bootstrap.js` (שם, אייקון, הפעלה ישירה של node בלי cmd). כדי לשנות את השם משנים את `SHORTCUT_NAME`, ואת השם הישן מוסיפים ל-`OLD_SHORTCUT_NAMES`. כדי לשנות את האייקון מחליפים את `kashrut.ico`. במחשב המועצה, `auto-publish.ps1` מעביר לבד קיצור דרך שעדיין מצביע על `start.bat` (חסום שם) להפעלת node. את קיצורי הדרך של ניהול משגיחים ומעקב אאוטלוק הוא מעביר להפעלה דרך `launch-app.js` (node, בלי PowerShell, שנחסם על ידי האנטי-וירוס). האייקונים שלהם נמצאים ב-`icons\<שם תיקיית האפליקציה>-<מספר>.ico` (אייקון חדש מקבל מספר חדש, כי Windows שומר אייקונים לפי שם הקובץ), ומוגדרים לקיצור הדרך אוטומטית במחשב המועצה. בקבלת הפרסום (`last-auto-publish.txt`) מופיעים גם קיצורי הדרך של המחשב ויומן ההפעלה (`launch.log`).

## גישה מהמחשב השני (מנהרה)

כשאתר "שירת הים" חוסם רשת מסוימת, אפשר להשתמש באפליקציה שרצה במחשב שבו הכניסה עובדת:

1. במחשב שבו האפליקציה עובדת: מפעילים אותה כרגיל, ואחר כך את `remote-tunnel.bat`. בפעם הראשונה הוא מתקין את cloudflared. הוא פותח מנהרה, שומר את הכתובת ב-`tunnel-url.txt` ודוחף אותה ל-GitHub. המנהרה פתוחה כל עוד החלון פתוח, ו-Ctrl+C סוגר אותה כמו שצריך.
2. במחשב השני: מפעילים את `open-remote.bat`. הוא מושך את הכתובת מ-GitHub ופותח אותה בדפדפן.

הכתובת משתנה בכל הפעלה, וכל מי שמחזיק בה יכול להגיע לדף הכניסה. לכן כדאי לסגור את המנהרה כשלא משתמשים בה.

אחרי שהאתר עולה ב־HTTPS:
- **אייפון (Safari)**: שיתוף ← "הוסף למסך הבית".
- **אנדרואיד (Chrome)**: תפריט ← "התקן אפליקציה".

## אבטחה

- מי שיש לו גישה לשרת יכול להשתמש בחיבורים הפעילים. לכן כדאי להפעיל את השרת רק עבורך או עבור הצוות, ולא כשירות ציבורי.
- בקשות שמשנות נתונים מחייבות כותרת `X-App`, כהגנה בסיסית מפני CSRF.
- השרת מעביר רק את קריאות ה־API שמוגדרות ב־`server.js`, ולא כל קריאה לאתר.
- כדאי לוודא מול המשרד לשירותי דת שמותר להשתמש במערכת בצורה כזו.

## נקודות API של האתר שבשימוש

| פעולה | נקודה באתר |
|---|---|
| כניסה | `POST /Authentication` (LoginName, Password, AuthorityID) |
| רשימת בתי עסק | `GET Data/Site/GetSearchSites` |
| פרטי עסק / עדכון | `GET Data/Site/GetSiteDetails`, `POST Data/Site/UpdateSite` |
| כתובת ומיקום / עדכון | `GET Data/Site/GetSiteAddresses`, `POST Data/Site/UpdateSiteAddress` |
| תעודות כשרות | `GET Data/Site/GetCertificateRequests` |
| דיווחי משגיחים | `GET Data/Site/GetSiteSupervisorReport` |
| תמונת מצב | `GET Data/General/GetHomePageDetails` |

אחרי כל פרסום אוטומטי נכתבת קבלה בקובץ `last-auto-publish.txt` ב-GitHub.
- `last-auto-publish.txt` כולל גם את פלט הפרסום (למשל אם Node וסקריפט ההתקנה נמצאים בתיקייה המשותפת).
